# 隐私与数据流

> 对应当前源码 · 2026-09-08

Earshot 没有账号、托管中继或自建遥测服务。云端识别使用用户自己的 DashScope 账户；它不是离线转写应用。

## 本机保存什么

正式应用通常使用 `~/Library/Application Support/Earshot/`，路径由 Electron `appData` 下的 `Earshot` 子目录确定。

| 数据 | 保存与用途 |
| --- | --- |
| API 密钥 | `key`，明文，文件权限 `0600`；不使用 Keychain 或应用层加密 |
| 录会音频 | 每场会的 `mic.wav` 与 `system.wav`，用于回听和转写重试 |
| 导入音频 | 会话中的 `original.wav/mp3/m4a` 原文件副本与规范化 `system.wav`，原始来源文件不修改 |
| 修正与标记 | `corrections.json` 保留单段修改历史和原稿来源，`bookmarks.json` 保存时间标记；搜索在本机执行 |
| 热词 | `hotwords.json`，词表、云端词表 ID、状态及账户摘要，不保存另一份 Key |
| 用量 | `usage.json`，模型、音频时长、Token、计量来源和完成状态，不保存录音或转写内容；保留最近 366 天、最多 10,000 次请求 |
| 稿件与会话信息 | 会话 JSON / JSONL、时间戳、标题、任务状态和本场名字 |
| 语音输入 | 保存识别原稿及最终文字；音频临时保留在内存供当前识别/重试 |
| 人物和声纹 | 全局名字、稳定人物 ID、CAM++ 向量、模型与音频片段来源，本机提取匹配 |
| 任务恢复 | 云端 task ID、音频指纹、阶段、HTTP 状态及安全 request ID；用户命名后的声纹登记状态 |
| 实时连接诊断 | 会话内 `realtime-events.json`，最多 200 条事件、权限 `0600`；仅时间、音轨、重试次数/间隔、分类、允许的错误码及本机生成的任务 ID，不含原始错误消息、正文、音频或 Key |
| 设置 | 自动区分、共用麦克风、快捷键、插入方式和模型选择 |

`0600` 限制其他普通系统账户读取密钥，不能防止当前用户权限下的其他程序或管理员读取。录音和稿件同样没有应用层加密；磁盘备份和同步工具可能复制这些文件。

## 什么会离开本机

- 开始录会后，双轨音频通过 DashScope WebSocket 实时识别。
- 停录后，WAV 上传到 DashScope 返回的上传地址，再提交文件识别任务；启用自动区分时处理说话人分离。
- 语音输入通过 DashScope 流式接口发送麦克风音频。
- 保存热词会向百炼同步支持模型的词表；Qwen Audio 3.0 的热词随识别请求发送。热词可能包含用户输入的人名、公司和术语。
- 修改热词时创建新的云词表，已开始的请求继续使用原版本。应用不会自动修改或删除旧云词表，以免影响仍在处理的任务；清空本机热词只停止后续携带，不等于删除服务商保存的旧词表。旧词表占用账户词表额度，可在所有任务结束后通过百炼管理；额度不足会明确显示同步失败。
- 开启可选文字润色时，识别文本发送到 DashScope 的兼容 Chat API；默认关闭。
- 安装依赖和下载可选声纹模型会连接 npm、Electron/GitHub 或模型下载托管服务。运行期声纹提取和匹配在本机完成。

Provider 端点和模型可在 `src/main/providers/`、`src/shared/model-settings.ts` 核对。API key 输入只经 preload 交给主进程；主进程向服务商鉴权，渲染快照仅返回是否已配置。应用不在默认日志主动记录密钥，但分享日志前仍应自行检查其中的路径、错误及内容。

服务商的数据保留、账单与使用条款由服务商决定；本项目不承诺其保存期限或删除结果。删除本机会话不会调用服务商数据删除接口。

## 权限与跨 App 输入

录会需要麦克风和屏幕/系统音频权限。语音输入使用麦克风，跨应用粘贴需要辅助功能权限。无法读取目标控件不会阻止录音与识别。自动填入在可读取时通过 Accessibility 比较原文字、选区与输入后的结果；这些目标文字只在内存中使用，不作为润色上下文发给云端。已知应用、窗口、输入位置或安全输入状态变化时不派发。

自动填入统一使用临时系统剪贴板和一次 Cmd+V，不自动按 Enter。原剪贴板按 item/type/data 保存在主进程内的单个 Worker 线程内存中，不写入磁盘或日志。最多保存 64 个 item、每项 64 种格式、合计 16 MiB；文件 promise、无法读取、超限或读取超时的内容会阻止本次自动填入，识别文字保留供复制。

派发后，只有文本与光标实际符合预期才显示已填入；不可核验时提示检查输入框，不自动补发。开始粘贴前的目标检查与操作系统消费键盘事件不是原子的；不可读控件内的切换可能无法检测，不能用于密码等受保护输入。可核验路径至少等待约 500 ms、不可核验路径约 1000 ms 后尝试恢复剪贴板，这不是任意应用都已读完的保证。可在设置关闭自动填入，改为手动复制。

恢复同时检查剪贴板版本与随机会话标记；用户后来复制了新内容，即使文字相同，也不会被旧快照覆盖。正常退出等待清理；恢复仍未完成时应用保持打开并说明原因。进程崩溃可能丢失内存中的原剪贴板，临时文字可能留在系统剪贴板，应用不承诺崩溃恢复。系统剪贴板可能被其他应用、剪贴板管理器或系统同步读取。

点击「复制文字」是主动替换系统剪贴板的操作，不再恢复此前内容。旧「微信兼容输入」偏好保留读取兼容，但不再启用单独的微信输入路径；所有应用使用相同的目标检查与结果语义。

## 删除与反馈

会话删除在撤销期后移除本场目录；已经导出的文件、全局人物、声纹、热词及用量记录不会同时删除。需要完全移除本机数据时，停止录音并退出应用，再手动移除上述 `Earshot` 数据目录；这也会清除密钥和设置。

提交 Issue 时使用合成样例，移除密钥、私人录音、姓名、原始转录及本机路径。安全问题见 [SECURITY.md](../SECURITY.md)。
